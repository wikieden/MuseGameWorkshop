## 1. 用途

本文件是从文档设计阶段进入 v0.1 Workflow Pack MVP 落地前的执行评审件。

它把 `v0.1-manifest.zh.md` 中的范围转成可 review 的执行顺序、文件计划、验收方式和风险控制。它本身不是动手批准；只有 review gate 明确为 `Approved` 后，才可以创建或修改 `AGENTS.md`、`.agents/skills/`、`templates/`、`tools/checks/` 和 dry-run evidence。

本文件服务三个目标：

- 让制作人 / Producer 能看懂 v0.1 是否控范围。
- 让 AI coding tools 能看懂下一步该先计划、后执行。
- 让中文和英文用户群体进入同一个 workflow core，但使用各自自然的游戏制作语言。

## 3. 本轮需要 Review 的决策

review 时需要明确回答：

| 决策点 | 推荐决策 | 影响 |
|---|---|---|
| v0.1 是否只落 workflow pack | 是 | 避免示例游戏提前吞掉产品本体。 |
| 是否在当前 workspace 内落地 | 是 | 让文档、规则、skills、templates 和 checks 在同一项目内闭环。 |
| 是否严格按 `v0.1-manifest.zh.md` 落 14 个 skills、22 个 templates、5 个 checks | 是 | 保持 v0.1 范围可验收。 |
| 是否先做 Boss Rush 无代码 dry run | 是 | 验证流程，不提前进入游戏实现。 |
| 是否让 Codex、Claude Code、Kiro CLI、opencode 等工具共享同一套 review gate | 是 | 保持 AI tool-agnostic。 |
| 是否所有模板保留中英文/地区语境 metadata | 是 | 支持中文和英文两类用户群体。 |

review gate 只能给出三种状态：

- `Approved`：可以按本文件执行 v0.1 落地。
- `Needs revision`：先修改本文件或 manifest，再重新 review。
- `Rejected`：停止 v0.1 落地，重新讨论方向。

## 4. 执行原则

1. Review first / 先评审：任何结构、代码、资产改动前都先输出设计摘要和执行计划。
2. Workflow first / 先工作流：v0.1 产物是规则、skills、templates、checks 和 dry run 证据。
3. Tool-agnostic / 工具无关：Codex、Claude Code、Kiro CLI、opencode 等工具都应能读取同一套规则。
4. Game-industry language / 游戏行业语言优先：对外叫法使用 Concept、Pre-production、Prototype、Vertical Slice、Playtest、QA 等行业能理解的制作语言。
5. AI-native evidence / AI 工作流证据保留：prompt、工具、license、review、test result、decision record 必须能落盘。
6. Bilingual-ready / 双语可用：中文文档使用中国游戏界术语，英文文档使用自然英文 production language。
7. No premature game code / 不提前写游戏代码：Godot playable prototype 从 v0.2 开始。

## 7. 执行顺序

1. 记录 review gate：确认本文件状态为 `Approved`。
2. 运行文档静态检查：确认现有文档链接、中英文配对和启动 prompt 没有回归。
3. 创建 `AGENTS.md`：把 review-first、tool-agnostic、asset provenance、bilingual-ready 和 no premature game code 写入项目规则。
4. Review `p0-skill-skeleton-plan.zh.md`：确认 14 个 P0 skill skeleton 的统一结构、验收方式和禁止范围。
5. 创建 `.agents/skills/`：在 P0 skill skeleton plan 的 review gate 为 `Approved` 后，先落 14 个 P0 skill skeleton，再逐个填充可执行工作流。
6. 创建 `templates/`：按 manifest 落 22 个模板，统一 metadata block。
7. 创建 `tools/checks/`：实现 5 个检查入口，保持 `PASS` / `FAIL` 输出。
8. 运行检查并修正文档或模板缺口。
9. 执行 Boss Rush / 《反击试炼》无代码 dry run。
10. 写入 dry-run evidence 和 review-gate 结果。
11. 输出 v0.1 completion note，确认 Definition of Done。

## 8. 测试方式

v0.1 测试分四层。

### 8.1 文档测试

- 所有 README 和 docs 内本地 Markdown 链接存在。
- 所有核心文档中英文成对存在。
- 启动 prompt 包含 `overall project plan`、`v0.1 execution plan`、`P0 skill skeleton plan`、`v0.1 manifest`、`testing strategy`、`bilingual audience strategy` 和 review gate。

### 8.2 Skill Contract Tests

每个 skill 必须通过这些人工或脚本检查：

- 有 `Use When` 和 `Do Not Use When`。
- 有明确 `Inputs`、`Outputs`、`Workflow`、`Quality Bar`。
- 会修改项目结构、代码或资产的 skill 必须先要求设计摘要与执行计划。
- 输出能回到模板或 evidence 文件，不停留在聊天记录里。

### 8.3 Template Tests

每个模板必须：

- 以共享 metadata block 开头。
- 包含 `Language`、`Target Audience`、`Locale`、`Terminology Source`、`Owner`、`Review Status`。
- 不绑定单一 AI coding tool 或单一引擎。
- 能被中文用户和英文用户通过对应文档理解。

### 8.4 Dry Run Tests

Boss Rush / 《反击试炼》dry run 必须证明：

- AI tool 先读取文档和规则。
- AI tool 先输出设计摘要、执行计划、影响范围和 review 点。
- 不写游戏代码。
- 能把 pitch 转成 core loop、mechanic spec、engine mapping、playtest plan。
- review gate 记录有明确状态。

## 9. 主要风险与控制

| 风险 | 表现 | 控制方式 |
|---|---|---|
| 提前进入游戏实现 | v0.1 出现 Godot/Unreal 可运行代码 | `check-v0.1-manifest` 阻止，review gate 拦截。 |
| skill 写得像陌生 agent 体系 | 游戏行业用户看不懂 | skill 名称和说明映射到制作阶段、制作职能和交付物。 |
| 中英文不一致 | 英文文档少读项或中文文档缺术语对应 | `check-doc-pairs`、启动 prompt 检查和 glossary 检查。 |
| 模板过重 | 独立开发者不愿使用 | 保持模板短、可复制、能在 10-20 分钟内填第一版。 |
| creative AI 资产绕过 review | 资产只有文件，没有来源和授权记录 | asset brief、provenance、review 三件套必填。 |
| 工具绑定过早 | 只服务 Codex 或某个特定工具 | Tool adapter rules 只定义映射，不把 workflow 绑定到单一工具。 |

## 10. Review Checklist

review 时请检查：

- v0.1 是否仍然是 workflow pack，而不是游戏项目。
- 14 个 skills 是否足够覆盖 P0。
- 22 个 templates 是否足够支撑第一轮制作记录。
- 5 个 checks 是否能验收 v0.1。
- Boss Rush dry run 是否足够小、足够游戏行业可理解。
- 中文和英文用户入口是否都清楚。
- P1/P2 是否没有提前进入实现。

## 11. Approval Record

review 结论建议使用以下格式落到 `templates/production/review-gate.md` 或 dry-run evidence：

```md
## Review Gate

- Review Status: Approved | Needs revision | Rejected
- Reviewer:
- Date:
- Scope Reviewed:
- Required Changes:
- Notes:
```

只有 `Review Status: Approved` 时，才能进入 v0.1 落地执行。
