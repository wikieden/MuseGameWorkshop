# Muse Game Workshop v0.1 Manifest

版本：v0.1

语言：中文

## 1. 用途

本文件是 v0.1 首批落地范围的唯一清单。其他文档可以描述长期愿景、完整架构和后续版本，但 v0.1 实际创建文件、目录、skills、templates 和 checks 时，以本 manifest 为准。

v0.1 的目标不是做游戏代码，而是落一个可以被多种 AI coding tools 使用的 workflow pack，并用 Boss Rush 样板游戏完成一次无代码 dry run。

### 1.1 Full Target vs v0.1 Subset

Muse Game Workshop 文档中有两类范围：

- Full target / 最终全集：长期完整目录、完整 skill catalog、完整模板族和后续版本能力。
- v0.1 subset / v0.1 子集：当前版本真正允许创建和验收的文件、skills、templates、checks 和 dry-run evidence。

v0.1 实际落地时，本 manifest 是唯一真源。其他文档中的更大目录树、更多 skills 或更多模板，如果没有被本 manifest 明确列入，都视为后续版本或最终全集，不得在 v0.1 中提前 scaffold。

## 2. v0.1 发布目标

v0.1 必须完成：

- `AGENTS.md` 项目规则。
- 第一批 P0 workflow skills。
- 第一批 core templates。
- 第一批静态检查脚本规格。
- Boss Rush / 《反击试炼》无代码 dry run。
- review gate、handoff 和 evidence 记录方式。

v0.1 不包含：

- Godot 示例游戏代码。
- Unreal 示例游戏代码。
- 商业 creative tool API 接入。
- MCP 编辑器自动化接入。
- P1/P2 功能实现。
- manifest 未列出的 skill 或模板。

每个 `SKILL.md` 必须包含：

- `name`
- `description`
- `Use When`
- `Do Not Use When`
- `Inputs`
- `Outputs`
- `Workflow`

所有会修改项目结构、代码或资产的 skill 必须先输出设计摘要和执行计划，等待 review gate 通过后再执行。

## 8. Boss Rush Dry Run

v0.1 必须用 Boss Rush / 《反击试炼》完成一次无代码 dry run。

必须产出：

```text
docs/evidence/dry-runs/boss-rush-intake.zh.md
docs/evidence/dry-runs/boss-rush-plan.zh.md
docs/evidence/dry-runs/boss-rush-review-gate.zh.md
```

dry run 不写游戏代码，只验证：

- AI tool 是否先读文档。
- 是否输出设计摘要和执行计划。
- 是否引用正确 templates。
- 是否遵守 review gate。
- 是否能把下一步转成 Godot 示例计划。

规范 dry run 链路：

```text
game-intake
core-loop
mechanic-spec
vertical-slice-planner
engine-portability
creative-asset-pipeline
ux-flow
level-blockout
playtest-report
```

规范 dry run 产出必须收敛到上面 3 个 evidence 文件中，不额外创建模板实例文件。
