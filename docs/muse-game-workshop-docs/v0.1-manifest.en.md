# Muse Game Workshop v0.1 Manifest

Version: v0.1

Language: English

## 1. Purpose

This file is the single source of truth for the v0.1 delivery scope. Other documents may describe the long-term vision, full architecture, and later versions, but v0.1 file creation, directories, skills, templates, and checks must follow this manifest.

v0.1 does not build game code. It ships a workflow pack that multiple AI coding tools can use, then validates it with a no-code Boss Rush dry run.

### 1.1 Full Target vs v0.1 Subset

Muse Game Workshop documents describe two scopes:

- Full target: the long-term complete directory layout, full skill catalog, full template family, and later-version capabilities.
- v0.1 subset: the files, skills, templates, checks, and dry-run evidence that this version may actually create and validate.

During v0.1 delivery, this manifest is the single source of truth. Larger directory trees, additional skills, or additional templates in other documents are future-version or full-target material unless explicitly listed in this manifest, and must not be scaffolded early in v0.1.

## 2. v0.1 Release Goal

v0.1 must deliver:

- `AGENTS.md` project rules.
- The first P0 workflow skills.
- The first core templates.
- The first static check specifications.
- A no-code Boss Rush / Counter Trial dry run.
- Review gate, handoff, and evidence record patterns.

v0.1 does not include:

- Godot example game code.
- Unreal example game code.
- Commercial creative tool API integration.
- MCP editor automation integration.
- P1/P2 implementation.
- Skills or templates not listed in this manifest.

## 7. Required Checks

v0.1 must define and implement these check entry points:

```text
tools/checks/check-doc-links
tools/checks/check-doc-pairs
tools/checks/check-startup-prompts

```

Output format:

```text
PASS <check-name>
FAIL <check-name>: <reason>
```

v0.1 passes when:

- All local Markdown links exist.
- The root README exists; the core document set exists in Chinese and English pairs: overall project plan, Vision, PRD, technical architecture, Godot/Unreal workflow, skill pack spec, production language guide, bilingual audience strategy, terminology glossary, handoff contracts, templates, delivery plan, v0.1 execution plan, v0.1 manifest, testing strategy, and MVP roadmap.
- README, package indexes, roadmap, and testing strategy starting prompts include target language, target audience, bilingual audience strategy, v0.1 execution plan, P0 skill skeleton plan, v0.1 manifest, and review gate.
- CLAUDE.md must not conflict with AGENTS.md or the v0.1 manifest scope rules.
- Skills/templates/checks listed in this manifest exist.
- Every template includes the metadata block.
- v0.1 contains no premature game implementation files such as `*.gd`, `*.tscn`, `*.tres`, `*.uasset`, `*.umap`, `*.uproject`, `*.cpp`, `*.h`, `*.cs`, `*.shader`, or `*.import`.

## 8. Boss Rush Dry Run

v0.1 must run one no-code Boss Rush / Counter Trial dry run.

Required outputs:

```text
docs/evidence/dry-runs/boss-rush-intake.en.md
docs/evidence/dry-runs/boss-rush-plan.en.md
docs/evidence/dry-runs/boss-rush-review-gate.en.md
```

The dry run writes no game code. It validates:

- The AI tool reads docs first.
- It outputs a design summary and execution plan.
- It references the correct templates.
- It respects the review gate.
- It can turn the next step into a Godot example plan.

Canonical dry-run chain:

```text
game-intake
core-loop
mechanic-spec
vertical-slice-planner
engine-portability
creative-asset-pipeline
ux-flow
level-blockout
playtest-report
```

Canonical dry-run outputs must be consolidated into the 3 evidence files above. Do not create separate template instance files during v0.1.
