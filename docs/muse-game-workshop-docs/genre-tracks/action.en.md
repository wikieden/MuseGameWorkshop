# Action Track

Status: Draft  
Version scope: v0.8  
Review Status: Approved

## Player Promise

The player makes precise, readable, time-sensitive actions and gets immediate feedback.

## Core Loop Emphasis

```text
read threat -> choose movement / attack / defense -> execute timing -> receive feedback -> reposition -> repeat
```

## Required Deliverables

- Combat verb list.
- Input and timing spec.
- Enemy behavior brief.
- Hit, dodge, guard, parry, counter, and recovery state notes.
- Camera and feedback requirements.
- Playtest checklist for feel and readability.

## Prototype Validation

The prototype must prove input response, timing windows, threat readability, failure recovery, and feedback clarity before content volume.

## Asset And UX Needs

- Player/enemy silhouettes must be readable.
- Attack tells, hit reactions, selection, damage, and danger zones need clear temporary feedback.
- A mannequin-style robot proxy or equivalent readable prototype asset is acceptable if provenance and license are recorded.

## QA And Playtest Checks

- Can the player identify threat, range, and timing?
- Are failed inputs understood as player error, tuning issue, or unclear feedback?
- Does the camera preserve action readability?

## Explicit Exclusions

- Final animation quality.
- Full enemy roster.
- Final VFX/audio mix.
- Release tuning.
