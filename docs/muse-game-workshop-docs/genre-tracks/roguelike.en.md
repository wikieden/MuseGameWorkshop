# Roguelike Track

Status: Draft  
Version scope: v0.8  
Review Status: Approved

## Player Promise

The player takes a run through uncertain choices, accepts risk, builds power, and learns from failure.

## Core Loop Emphasis

```text
start run -> face encounter -> choose risk/reward -> gain resource or power -> adapt build -> fail or finish -> improve next run
```

## Required Deliverables

- Run structure.
- Encounter pool.
- Reward and upgrade table.
- Resource pressure model.
- Failure and recovery notes.
- Procedural content constraints.
- Playtest checklist for run pacing and decision quality.

## Prototype Validation

The prototype must prove that each run produces meaningful decisions, readable risk, and a reason to try again.

## Asset And UX Needs

- Room, node, or encounter markers must communicate risk and reward.
- Upgrade choices need readable category and tradeoff markers.
- Prototype visuals can be symbolic if decision readability is strong.

## QA And Playtest Checks

- Can players understand why a run succeeded or failed?
- Are choices meaningfully different?
- Does randomness create variety without hiding rules?

## Explicit Exclusions

- Full procedural generation system.
- Large item pool.
- Meta-progression economy.
- Live balancing backend.
