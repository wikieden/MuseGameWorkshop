# Muse Game Workshop 术语表：中国游戏行业对应叫法

版本：v0.1

语言：中文

## 1. 使用原则

Muse Game Workshop 的所有核心英文术语都必须给出中国游戏行业能理解的中文对应。术语表是中英文用户体验之间的桥，不要求英文面向文档在正文里反复插入中文解释。

写法规则：

- 中文面向文档中，第一次出现时使用 `英文 / 中文行业叫法`。
- 英文面向文档中，优先保持自然英文表达；中文对应放在术语表、本地化说明或中国市场语境中。
- 后文可以只用中文，必要时保留英文。
- 如果中国游戏行业没有完全统一叫法，使用“推荐中文名 + 常见别名”。
- AI workflow 术语可以保留英文，但必须解释成中文工作含义。
- 不要只做直译；优先选择国内游戏团队实际会用的叫法。

示例：

- `Vertical Slice / 垂直切片`
- `Level Blockout / 关卡灰盒`
- `Asset Provenance / 资产来源与授权记录`
- `Review Gate / 评审节点`

## 2. 制作阶段术语

| English Term | 推荐中文叫法 | 常见别名 / 说明 | 使用建议 |
|---|---|---|---|
| Concept | 概念阶段 | 创意阶段、立项概念 | 用于判断方向、玩家幻想和核心风险。 |
| Pitch | 项目提案 | 一句话卖点、提案稿、立项 pitch | 面向制作人、团队或投资方说明项目。 |
| Pre-production | 预制作 | 预研、前期制作 | 国内团队常说“预研”；偏正式流程可用“预制作”。 |
| Prototype | 原型验证 | 玩法原型、Demo 原型 | 用最低成本验证核心乐趣。 |
| Demo | 演示版本 | Demo、试玩版、演示包 | 国内常直接说 Demo；面向玩家可说试玩版。 |
| Vertical Slice | 垂直切片 | 品质样片、小切片、完整体验切片 | 行业内常用“垂直切片”，说明一小段接近最终品质的完整链路。 |
| Production | 正式制作 | 量产、内容制作阶段 | 国内团队也常说“量产”。 |
| Playtest | 试玩测试 | 内部试玩、可玩性测试 | 强调观察玩家行为，不只是收集意见。 |
| Iteration | 迭代 | 调整轮次、版本迭代 | 用于基于反馈的改动。 |
| Polish | 打磨 | 体验打磨、手感打磨、表现打磨 | 不是新增大内容，而是提升完成度。 |
| QA | 测试 | 质量保证、功能测试、回归测试 | 国内常直接说“测试”或 QA。 |
| Release Readiness | 发布准备 | 发行准备、上线准备、提审准备 | Demo、Steam/itch、平台包都适用。 |
| Release | 发布 | 上线、发版、对外发布 | 根据平台语境选择“发布/上线/发版”。 |
| Postmortem | 项目复盘 | 复盘、阶段复盘 | 不建议直译为“尸检”。 |
| Milestone | 里程碑 | 节点、阶段目标 | 用于阶段验收。 |
| Greenlight | 立项放行 | 绿灯、立项通过 | 国内更自然说“立项通过”或“放行”。 |
| Content Lock | 内容锁定 | 内容冻结、范围冻结 | 发布前停止新增内容。 |
| Feature Freeze | 功能冻结 | 功能锁定 | 发布前只修 bug，不加新功能。 |
| Alpha | Alpha 版本 | 内部功能版 | 小团队不必强制使用。 |
| Beta | Beta 版本 | 测试版、外部测试版 | 公开或半公开测试阶段。 |
| Gold Master | 母盘版本 | 送审版本、金盘 | 主机/传统发行语境更多，小团队少用。 |

## 3. 制作职能术语

| Game Designer | 游戏策划 | 玩法策划、系统策划、关卡策划、数值策划 | 泛称用“游戏策划”，具体可细分。 |
| System Designer | 系统策划 | 系统设计 | 负责系统规则和模块。 |
| Combat Designer | 战斗策划 | 战斗设计 | 适合动作/射击/ARPG 等项目。 |
| Level Designer | 关卡策划 | 关卡设计 | 负责关卡结构、节奏、遭遇。 |

| Technical Designer | 技术策划 | 玩法技术策划、技术向策划 | 国内不是所有团队都有该岗位，解释为“把设计转成可实现规格”。 |
| Gameplay Programmer | 玩法程序 | 逻辑程序、客户端玩法程序 | 实现输入、状态、交互和反馈。 |

| Technical Artist | 技术美术 | TA | 负责材质、VFX、导入规格、性能预算。 |

| VFX Artist | 特效美术 | VFX、特效 | 负责技能、打击、环境特效。 |
| UI Artist | UI 美术 | 界面美术 | 负责界面视觉。 |
| UX Designer | 交互设计 | UX、用户体验设计 | 游戏团队也常说“交互/体验”。 |
| Composer | 作曲 | 音乐设计、配乐 | 负责音乐主题、loop、情绪。 |
| Sound Designer | 音效设计 | 音效师、声音设计 | 负责反馈音效、环境声和混音意图。 |

| Release Manager | 发布负责人 | 版本负责人、发行对接、上线负责人 | 负责构建、版本、平台清单和发布风险。 |
| Localization Manager | 本地化负责人 | 本地化 PM | 负责翻译、术语表、LQA。 |

## 8. 使用要求

后续新增文档时必须遵循：

1. 新核心英文术语必须在术语表中加中文对应。
2. 新增 skill、模板或检查项时，如果术语不在本表中，先补术语表。
3. 中文面向文档中新英文术语第一次出现必须加中文行业叫法。
4. 英文面向文档优先使用自然英文表达，不把中文解释塞进主文案。
5. AI workflow 内部术语可以保留英文，但必须提供中文解释。
6. 不使用生硬直译替代国内团队已有叫法。

推荐格式：

```text
Vertical Slice / 垂直切片
Asset Provenance / 资产来源与授权记录
Dry Run / 流程演练
Review Gate / 评审节点
```
